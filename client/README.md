# Client

The client is a Vite, React, and TypeScript application. Its current page is the BHVR starter demo at `src/routes/index.tsx`. TanStack Router provides routing, TanStack Query handles the demo request, and Tailwind CSS provides styling.

## Run

From the repository root:

```sh
bun install
bun run dev:client
```

Run `bun run dev:server` in another terminal to use the starter page's API button. The browser calls the current page origin. Vite proxies `/api` and `/hello` to Hono at `http://localhost:3000` by default. Set `API_PROXY_TARGET` in the root `.env` only when Hono uses another address.

For production, `bun run build` writes the client to `client/dist`, and `bun run start` has Hono return that build together with the API. The client uses the same `window.location.origin` configuration in both modes.

## Import aliases

Client imports can use `@assets/`, `@components/`, `@features/`, `@hooks/`, `@lib/`, `@routes/`, `@stores/`, `@styles/`, `@three/`, and `@utils/` paths rooted at `src/`. The general `@/` alias remains available. Keep `vite.config.ts` and `tsconfig.app.json` alias mappings aligned.

## Source ownership

- `src/main.tsx` creates the router and query client.
- `src/routes/` contains route files. `src/routeTree.gen.ts` is generated by the TanStack Router plugin; do not edit it manually.
- `src/index.css` contains the current global styles.
- The starter route imports the typed API helper from `server/client`; this working demo boundary is documented in the architecture guide.

The `features/`, `components/ui/`, `hooks/`, `stores/`, `lib/`, `three/`, and `styles/` paths are reserved for code that needs them. Create a directory with its first real file. See the root [README](../README.md), [file organization](../docs/file-organization.md), and [conventions](../docs/conventions.md) when adding code.
